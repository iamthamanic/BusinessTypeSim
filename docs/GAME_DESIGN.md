# Game Design — Business Type

## Core loop

```text
Situation
→ Informationen prüfen
→ Team befragen / Analyse anfordern
→ Entscheidung formulieren
→ Interpretation prüfen
→ Entscheidung festlegen
→ Simulation
→ Decision Review
→ Zeit vergeht
→ nächste Situation
```

## Design principle

Business Type ist kein Quiz mit einer versteckten richtigen Antwort. Das Spiel bewertet Entscheidungsqualität und späteres Ergebnis getrennt.

## Decision Quality

Sechs Dimensionen:

1. Framing
2. Information
3. Alternatives
4. Objectives
5. Reasoning
6. Execution

Ein schwacher Faktor soll den Gesamteindruck stärker begrenzen als ein einfaches arithmetisches Mittel.

## Information system

Informationen können bereits bekannt, durch Analyse verfügbar oder grundsätzlich unsicher sein. Analysen können Simulationszeit verbrauchen. Unsicherheit wird sichtbar gemacht und nicht als fehlende UI-Information versteckt.

## Time

Zeit ist ereignisgetrieben. Analysen, Projekte und Entscheidungen können unterschiedliche Zeitspannen auslösen. Verzögerte Konsequenzen erscheinen erst, wenn ihr Zeitpunkt erreicht ist.

## Company diversity

Szenarien unterscheiden sich nicht nur über Größe, sondern auch über Branche, Headcount, Managementebenen, operative Komplexität, Kundenabhängigkeit und Marktposition.

## MVP scenarios

- SaaS / Scale-up
- Produktion / Mittelstand
- Professional Services / kleines Unternehmen

## Non-goals for MVP

Kein Multiplayer, keine 3D-Welt, keine globale Echtzeitwirtschaft und keine künstliche XP-/Coin-Ökonomie.
